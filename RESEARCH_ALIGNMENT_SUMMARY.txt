DETAILED RESEARCH GAPS & SOLUTIONS

GAP 1: Structured Story Output
─────────────────────────────────
Research Section: 4.2
Current State: Manual K.C. Nag story generation
Risk: LLM might miss fields, create invalid structures
Solution: Use Instructor library + Pydantic schema
  - Define: MathProblemContextStructured
  - Enforce: JSON schema at API level
  - Guarantee: No hallucinations, all fields present
Time: 8 hours
Benefit: 10-15x safer, automated validation

Code snippet:
  from instructor import Instructor
  story = client.chat.completions.create(
    model="claude-3-5-sonnet",
    response_model=StoryContextStructured,  # SCHEMA ENFORCED
    messages=[...]
  )
  # GUARANTEED to be valid StoryContextStructured


GAP 2: Structured Options / Distractors
────────────────────────────────────────
Research Section: 4.2 (variant)
Current State: Manual misconception selection
Risk: Missing fields, inconsistent quality
Solution: LLM generates with Pydantic schema
  - Define: DistractorStructured (5-tuple format)
  - Enforce: Exactly 3 distractors, all fields filled
  - Validate: No duplicate misconception types
Time: 12 hours
Benefit: 100% quality assurance, no manual review needed

Schema enforces:
  ✅ value: The wrong answer option
  ✅ teaching_point: What's being tested
  ✅ misconception_type: Which misconception
  ✅ why_wrong: Specific error
  ✅ remediation_hint: How to fix


GAP 3: Caching & Pre-computation
──────────────────────────────────
Research Section: 7.2
Current State: Generate skeleton fresh every time (500ms)
Risk: 3500ms per question, cannot scale
Solution: Pre-compute skeletons, cache in Redis
  - Pre-compute: 5000 valid skeletons per chapter (off-peak)
  - Cache: In Redis with 30-day TTL
  - Fetch: 5ms instead of 500ms
  - Result: 3500ms → 3000ms question latency
Time: 15 hours
Benefit: 70% latency reduction, 10x scalability

Architecture:
  Off-peak: Pre-compute 5000 skeletons per chapter
  On-demand: Fetch skeleton (5ms) + LLM (3000ms) = 3005ms
  Traditional: Generate skeleton (500ms) + LLM = 3500ms


GAP 4: Validation Pipeline
──────────────────────────
Research Section: 6.4
Current State: No verification of answers
Risk: LLM hallucinations might slip through
Solution: Round-trip validation
  - Extract: Numbers from question text
  - Solve: Using SymPy deterministic solver
  - Verify: Answer matches stored answer
  - Retry: If validation fails, regenerate
Time: 5 hours
Benefit: 100% correctness guarantee, catch hallucinations

Example:
  Question: "Amar has 12 apples. How many if he had 5 more?"
  Extract: 12, 5
  Solve: 12 + 5 = 17
  Verify: Matches stored answer? ✅ YES → VALID


GAP 5: Tool Use (Multi-step Problems)
────────────────────────────────────
Research Section: 4.4
Current State: Single-step questions only
Risk: Cannot support complex multi-step problems
Solution: LLM with function calling
  - Define: Safe SymPy tools (factor, solve, find_gcd)
  - Allow: LLM to call tools with arguments
  - Execute: In sandboxed environment
  - Return: Results back to LLM for reasoning
Time: 20 hours
Benefit: Multi-step problem support, reduced hallucination

Example flow:
  Problem: "Factor 12 and find prime factors"
  LLM calls: factor_expression("x**2 + 5*x + 6")
  System executes: (x+2)(x+3)
  LLM calls: find_prime_factors(12)
  System executes: [2, 2, 3]
  LLM generates: Final answer with reasoning
